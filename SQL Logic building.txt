---------------------------------------------------------------------------SQL QUERY WRITING LOGIC-----------------------------------------------------------------
Think:

SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY

And remember what each one does:

WHAT → WHERE → FILTER → GROUP → FILTER GROUPS → SORT


🔑 Memorize this

GROUP BY = GROUP the rows
SUBQUERY = FIND → COMPARE/USE
CORRELATED = CURRENT ROW → FIND ITS GROUP'S ANSWER → COMPARE

And importantly, they can be used together. A query can have GROUP BY in the outer query and a subquery inside HAVING or WHERE.



WHAT do I want?        → SELECT
WHERE is the data?     → FROM
WHICH ROWS count?      → WHERE
HOW to group?          → GROUP BY
WHICH GROUPS count?    → HAVING
HOW to sort?           → ORDER BY
HOW MANY?              → LIMIT

---------------------------------------------------------------------------The logic w/ joins------------------------------------------------------------------

WHAT do I want?              → SELECT
WHERE is the main data?      → FROM
DO I need another table?     → JOIN
HOW do the tables connect?   → ON
WHICH ROWS count?            → WHERE
HOW do I group?              → GROUP BY
WHICH GROUPS count?          → HAVING
HOW to sort?                 → ORDER BY
HOW MANY?                    → LIMIT



“Give me the top 3 departments whose average salary is above 5000, considering only employees earning more than 3000, with the highest average salary first.”


WHAT do I want?
→ Department + average salary
→ SELECT department, AVG(salary)


WHERE is the data?
→ employees table
→ FROM employees


WHICH employees count?
→ Salary > 3000
→ WHERE salary > 3000


HOW do I group them?
→ By department
→ GROUP BY department


WHICH departments count?
→ Average salary > 5000
→ HAVING AVG(salary) > 5000


HOW do I sort?
→ Highest average salary first
→ ORDER BY AVG(salary) DESC


HOW MANY?
→ Top 3
→ LIMIT 3


------------------------The result:------------------------

SELECT department, AVG(salary)
FROM employees
WHERE salary > 3000
GROUP BY department
HAVING AVG(salary) > 5000
ORDER BY AVG(salary) DESC
LIMIT 3;


--------------same exammple but with joins-----------------


WHAT do I want?
→ Department name + average salary
→ SELECT


WHERE is the data?
→ employees table
→ FROM


DO I need another table?
→ Yes, department name is in departments
→ JOIN


HOW do I connect them?
→ Match department_id
→ ON employees.department_id = departments.department_id


WHICH employees count?
→ Salary > 3000
→ WHERE


HOW do I group them?
→ By department
→ GROUP BY


WHICH departments count?
→ Average salary > 5000
→ HAVING


HOW do I sort?
→ Highest average salary first
→ ORDER BY ... DESC


HOW MANY?
→ Top 3
→ LIMIT

------------------------The result:------------------------

SELECT departments.department_name, AVG(employees.salary)
FROM employees
JOIN departments
    ON employees.department_id = departments.department_id
WHERE employees.salary > 3000
GROUP BY departments.department_name
HAVING AVG(employees.salary) > 5000
ORDER BY AVG(employees.salary) DESC
LIMIT 3;

--------------------------SUBQUERY--------------------------

SUBQUERY = FIND → OUTER QUERY = USE



So when you see a subquery problem:

1. What do I need to FIND first?
↓
2. Write that as the subquery
↓
3. Put it in ( )
↓
4. USE its result in the outer query

One caveat: some advanced problems use correlated subqueries, EXISTS, IN, ANY/ALL, etc. But even there, the core idea remains:

FIND something → USE that result to solve the main query.


Question:
"Who earns more than the average?"

        ↓

FIRST → What is the average?
        ↓
SECOND → Who is above that average?



the logic: 
MAIN QUERY
"Who spent more than average?"
          ↓
          │
          ↓
SUBQUERY
"What is the average?"
          ↓
       700
          ↓
MAIN QUERY
"Find customers spending > 700"
          ↓
      Sara, Mike



the result:
SELECT name, total_spent
FROM customers
WHERE total_spent > (
    SELECT AVG(total_spent)
    FROM customers
);



----------------------------------CORELATED SUBQERY--------------------------------------


When you see a subquery problem, ask these questions in order:

1️⃣ Do I need another query first?
NO → No subquery needed.
YES → Continue.
2️⃣ Does the inner answer depend on the current outer row?
NO → 🟢 NORMAL subquery
YES → 🔴 CORRELATED subquery
3️⃣ Look for these clues

Normal → “overall”, “all”, “company average”, “total average”
Correlated → “their own”, “its own”, “for each”, “respective”, “same category/department”





🟢 Normal Subquery
Problem: Find employees earning more than the overall company average.

SELECT employee_name, salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);

Logic:

Find one overall average → compare every employee against it.
ALL employees
     ↓
ONE company average
     ↓
Compare every employee


🔴 Correlated Subquery
Problem: Find products costing more than the average price of their own category.

SELECT p.product_name,
       p.price,
       p.category_id
FROM products p
WHERE p.price > (
    SELECT AVG(p2.price)
    FROM products p2
    WHERE p2.category_id = p.category_id
);


Same products table
        ↓
 ┌───────────────┐
 │       p       │  ← Outer perspective
 │       p2      │  ← Inner perspective
 └───────────────┘
        ↓
p2 uses information from p
        ↓
RELATED ANSWER



Logic:
Take current product → find its category average → compare its price.

CURRENT product
      ↓
ITS category
      ↓
ITS category average
      ↓
Compare CURRENT product price
⭐ The ultimate shortcut

Same answer for everyone? → NORMAL
Answer changes for each row? → CORRELATED

Normal:
employee salary > overall average

Correlated:
product price > its category average





---------------------------------------------------------------------------------how the query is executed------------------------------------------------------

How queries are executed:
One subtle thing: you usually write SELECT first, but SQL logically processes the query roughly from FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY.
