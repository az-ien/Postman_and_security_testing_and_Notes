Selenium java:

differnece between playwright and selenium 

👉 Selenium = Uses WebDriver — a separate bridge program that your automation talks to.
👉 Playwright = No WebDriver — it talks directly to the browser through its own communication channel.

Connection / Protocol

🔹 Selenium: Uses WebDriver, a standardized protocol where each command (click, type, navigate) is sent over HTTP to a browser‑specific driver (like ChromeDriver). This provides wide support but adds overhead.
🔹 Playwright: Does not depend on WebDriver. Instead, it talks directly to the browser engine using internal browser protocols like the DevTools Protocol (WebSocket‑based), giving more direct and efficient control.

---------------------------------------------------------------------------JS Executor vs Actions class------------------------------------------------------------------------------------

JavaScriptExecutor

Runs raw JavaScript inside the browser.
Great for things like: scroll the page, force a click, read or modify the DOM when WebDriver can’t.
Useful when elements are hidden, behind overlays, or when standard commands don’t work.

🖱️ Actions

Simulates real user interactions (mouse/keyboard), such as hover, move, drag‑and‑drop, click after moving to element.
Useful when simple click() fails because the element needs to be hovered or focused first.


-----------------------------------------------------------------------------------POM vs Page factory--------------------------------------------------------------------------------

In playwright there is no page factory only classes then their objects and calling those objects like normals classes
The core difference is that the Page Object Model (POM) is a design pattern, while Page Factory is a built-in class provided by Selenium WebDriver to implement the POM pattern more efficiently.
| Aspect                  | **POM (Page Object Model)**                                           | **Page Factory**                                                              |
| ----------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **Type**                | Design *pattern*                                                      | Selenium *implementation/helper* of POM                                       |
| **Element Definition**  | Uses traditional locators like `driver.findElement(By...)` in methods | Uses `@FindBy` annotations on fields                                          |
| **Initialization**      | Manual — you write code to locate elements                            | Automatic — PageFactory does it for you (`initElements`) ([GeeksforGeeks][1]) |
| **Code Boilerplate**    | More — locators and initialization in methods                         | Less — cleaner code thanks to annotations                                     |
| **Lazy Initialization** | ❌ Generally no lazy loading                                           | ✅ Elements are initialized only when used (lazy) ([GeeksforGeeks][1])         |
| **Usage**               | Manual POM can be used in any framework                               | Page Factory is specific to Selenium and supports annotation usage            |

[1]: https://www.geeksforgeeks.org/software-testing/page-object-model-and-page-factory-in-selenium-using-java/?utm_source=chatgpt.com "Page Object Model and Page Factory in Selenium Using Java - GeeksforGeeks"





-----------------------------------------------------------WAITS---------------------------------------------------------------------------


✔ Static Wait = wait exactly the time you give (like Thread.sleep()). 
TutorialsPoint
✔ Dynamic Wait = wait until a condition is met, up to a timeout, and stops early when possible (like Implicit/Explicit/Fluent Wait).

Static wait: Stop and wait — always the same time.
Dynamic wait: Wait until ready — stop early if possible.



| Feature             | Implicit Wait               | Explicit Wait                           |                 |
| ------------------- | --------------------------- | --------------------------------------- | --------------- |
| Scope               | Global for whole driver     | Specific to an element/condition        |                 |
| Use Case            | Basic delay for findElement | Wait for conditions (visible/clickable) |                 |
| Precision           | Less precise                | Very precise                            |                 |
| Requires Condition? | No                          | Yes (e.g., `visibilityOf`, `clickable`) | ([TestGrid][1]) |

[1]: https://testgrid.io/blog/waits-in-selenium/?utm_source=chatgpt.com "Selenium Waits Tutorial: Implicit, Explicit, and Fluent Waits"


// IMPLICIT WAIT -- wait up to 10 seconds for elements
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));

// Now find elements normally
driver.findElement(By.id("someElement")).click();


// EXPLICIT WAIT -- wait up to 10 seconds for element to be clickable
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
WebElement button = wait.until(
    ExpectedConditions.elementToBeClickable(By.id("loginButton"))
);

// now click when clickable
button.click();



//Fluent wait -- handles more conditions, can ignore exceptions 

| Feature                 | **Explicit Wait**      | **Fluent Wait**                               |                               |
| ----------------------- | ---------------------- | --------------------------------------------- | ----------------------------- |
| Based on                | WebDriverWait          | FluentWait                                    |                               |
| Condition type          | Yes                    | Yes                                           |                               |
| Custom polling interval | ❌ (fixed/default)      | ✔ (customizable)                              |                               |
| Exception ignoring      | Limited                | ✔ Can configure which exceptions to ignore    |                               |
| Flexibility             | Medium                 | High                                          |                               |
| Use case                | Standard dynamic waits | Unpredictable load times & complex conditions | ([Test Automation Studio][1]) |

[1]: https://www.testautomationstudio.com/blog/selenium/explicit-wait-vs-fluent-wait/?utm_source=chatgpt.com "Selenium - Explicit Wait vs Fluent Wait | Test Automation Studio : Selenium Blog"


Wait<WebDriver> wait = new FluentWait<>(driver)
      .withTimeout(Duration.ofSeconds(30))        // max wait time
      .pollingEvery(Duration.ofSeconds(5))        // check every 5 seconds
      .ignoring(NoSuchElementException.class);    // ignore this exception

WebElement element = wait.until(
    ExpectedConditions.visibilityOfElementLocated(By.id("someId"))
);
