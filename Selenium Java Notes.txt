differnece between:
findElement(locator parameter)  --  returns single WebElement, stored in one WebElement variable
findElements(locator parameter)  -- returns multiple WebElements, stored in WebElements list
 
 
secnario 1: Locator Loc matching with single WebElement
findElement(Loc)---->single WebElement  return type: WebElement
findElements(Loc)---->single WebElement  return type: list<WebElements> 


scenario 2: Locator Loc is matching with multiple WebElements
findElement(Loc)---->first WebElement  return type: WebElement
findElements(Loc)---->multiple all WebElements  return type: list<WebElements> 



scenario 3: Locator Loc is not matching with any WebElements
findElement(Loc)---->No such Element Exception
findElements(Loc)---->returns 0 (duhhh !!!)but no exception so an empty list is created

--------------------------------------------------------------dataprovider----------------------------------------------------------------
@dataProvider --- testmethod rquires test data: example login method for 2-3 users so one test but 3 user data
this data method is the data provider. 5 times data then it will send data 5 times without loops which are used to pick data one by one in each iteration
data is in the data provider method
but if there is huge data then there should be an excel file then the data provider will read the excel file and store in 2D array and return that array to the test code 
each row will go to 2D array then pass the array to the test method and it will run that as many times as there is data 
which is actual data driven testing.




-------------------------------------------------------parallel testing using xml file---------------------------------------------------

xml file parameter  pass to test pass to test method


---------------------xmlfile------------------

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE suite SYSTEM "http://testng.org/testng-1.0.dtd">



<suite name ="groupingsuite" parallel ="tests"> // parallel key word will run the three browser tests in parallel at the same time 
//this parallel can be kept in tests but then the syntax will be parallel ="classes", if parallel is kept in parent then the syntax has to have child
//thread-count =5 , this is optional but it creates 5 threads/processes if it is not added then only one thread/process is created, maximum 2-5 otherwise system might hang due to memory allocation
//multiple parameters can be passed like URL and then the test method will receive another parameter 

<test name ="chrometests">
<parameter name ="browser" value ="Chrome"/> // this is where parrametter sent
<classes>
